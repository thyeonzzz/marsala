# 对外输出规则

当 agent 使用者向**客户**展示能力或交付策略方案时，适用以下规则。

---

## 核心原则

同一套方法论，直接对外。技能文件是单版本的可执行知识，不存在另一套独立文件。交付件用客户的语言讲判断——输出方法论与策略论据，不输出系统内部的称谓、机制与操作语言。

---

## 对外不出现清单

对外输出中**不出现**以下内容：

- 模块架构称谓（"模块一""模块三""客户总监"等）
- 证据等级标签（E1-E6）
- 技能文件名与系统内部引用
- 校验规则编号（"校验一""校验三"等）
- agent 内部调度逻辑（"模块三产出后传递给模块六"）
- 对 agent 自身的操作指令（"你必须""禁止""注意事项"中以 agent 为对象的条目）
- 经验沉淀区内容
- 工具安装与调用细节（pymc-marketing、Agent Reach 等）

---

## 保留与转换

| 保留 | 转换方式 |
|------|---------|
| 方法论框架（矩阵、模型、分析维度） | 直接使用，不标注出处文件或模块 |
| 决策规则和判断标准（如"LTV:CAC ≥ 3:1"） | 保留规则，去掉推导过程 |
| 创意评估测试（去Logo测试、竞争复制测试等） | 作为分析方法呈现，不说明它属于系统哪个校验环节 |
| 数据来源和局限性 | 文末统一列出，文中引数据时简要标注来源类型 |
| 不确定性和风险 | 保留，这是策略可信度的一部分 |

---

## 语气

- 用 **"我们"** 自称，不用"agent""Marsala"
- 直接给结论，再展开论据。不先说"我们做了以下分析"
- 不解释分析方法论（除非客户追问）
- 承认信息不足和边界——不编造

### Action Titles：标题必须是完整断言

**硬性法则：每个章节标题必须是完整的结论句，永远不能是话题标签。**

| ❌ 话题标签 | ✅ 完整断言 |
|------|------|
| "市场分析" | "敏感肌修护品类规模 320 亿但增速放缓至 8%" |
| "竞品格局" | "薇诺娜 / 可复美 CR4 占 70%，新品牌未形成差异化替代" |
| "消费者洞察" | "62% 的敏感肌用户买护肤图稳不图新——安全是压倒性的购买动机" |
| "建议" | "用'压力肌'场景叙事替代'天然+科学'品类同质化话术" |

**验收标准：** 只读所有章节标题，必须连成一篇有说服力的短文。如果只读标题看不出完整的论证逻辑——标题不合格。这条检验叫 Ghost Deck 横向逻辑测试。

### Ghost Deck 横向逻辑测试

**在输出交付件之前，抽出所有章节标题，只读标题。** 标题连起来必须是一篇能独立站住的论证短文——包含情况、冲突、判断、行动。如果只读标题感到逻辑跳跃或缺少某一步——不是一个标题的问题，是整份交付件的结构缺失了这一步。

**为什么这是必须的：** 客户老板往往只看标题就做判断。如果他能从标题里读懂完整逻辑——你赢了。如果他需要读正文才能理解你想说什么——你输了。

---

## 交付件必备模块（七件套 + 三件套）

不强制套模板，但完整交付件必须包含以下模块，缺任何一件都退回补全：

1. **Executive Summary（一页）**：结论 + 三条关键证据 + 最大风险 + 下一步（要客户拍板/提供什么）。CEO 只看这一页就能决定是否往下读。
2. **三层目标**：品类目标（心智占位词/场景）／人群目标（动机+场景）／营销或验证目标（可度量结果）。每层给出度量方式与基线/占位，禁止只给单层目标。
3. **分析论证**：数据 → 洞察 → 判断。**洞察到创意的推导必须标注**——哪条洞察推出哪个动作，为什么是它而不是别的；说不清推导线的洞察只是素材。
4. **策略建议**：方向 + 理由 + 竞品对比 + 风险评估。
5. **投资概览**：预算结构表（构成/比例方向/金额/来源）。金额只填有依据的数字；无依据标「占位」，见「投资与目标量化的来源纪律」。
6. **反事实归因**：不做会怎样；品类增量 ≠ 品牌增量；排除替代解释。效果类指标必须回答「如果没做这件事，同期会是多少」。
7. **风险与纠错**：关键不确定性、独特预测、纠错机制、试验成本承担。
8. **复盘清单**：交付后/战役后的复盘问题（哪些判断被验证/被推翻、客户最在意哪一页、下次补什么）。
9. **下一步**：需要品牌方确认和提供的事项（数据、基线、预算）。
10. **数据来源**：文末列出所有来源及局限性。

### 内容层独立 + 提案蓝图（附件）

- **内容层是独立文档，必须连贯。** 文字答卷单独成立、单独可读，不依赖任何视觉化。硬标准：每一节只有一个主论点（一节一论点），信息密度过高的段落拆开。
- **提案蓝图是内容层的可选附件**，供视觉化接手者使用：逐页标注信息单元、视觉意图（这页讲什么、放什么图表、留什么白）。蓝图不改变内容层的完整性——删掉蓝图，内容层依然是一份完整的答卷。
- **呈现层（版式模板 / 精美 PDF）不在 Marsala 范围内。** 排版与设计由版式模板、设计工具或设计师承接；Marsala 判断「每页放什么信息」，不承担「怎么排才好看」。呈现层能力建设交由外部生态（更专业的模板库 / 设计技能）完成。

### Ghost Deck 横向逻辑测试（补充）

标题连成的短文必须能看出「情况 → 冲突 → 判断 → 行动」四步。缺了「行动」（下一步/纠错）或「冲突」（为什么是现在），整份交付件结构不完整。

---

## 投资与目标量化的来源纪律

**核心：Marsala 不产出凭空数字。** 投资额、目标值、效果预测，只来自三级来源——Marsala、挂载它的 agent 和 LLM 都不具备行业经验数字，行业经验通过客户输入与可查证基准进入系统：

| 来源级 | 内容 | 交付形态 |
|------|------|---------|
| **一级：品牌方输入** | 预算总额与构成、历史基线（搜索指数、动销、达人报价）、经营数据 | 直接使用，拆解费用构成；brief 没给预算时，把「预算」列为关键待确认项 |
| **二级：可查证行业基准** | 公开报告 / 同品类案例的预算结构、目标区间、比率关系 | 引用并标来源 + 时点 + 置信度，标注「待核实」；来源不明的不采用 |
| **三级：假设区间** | 一、二级皆无 | 给区间 + 推导逻辑 + 校准动作，明确标注「待验证」；**禁止写成精确数字** |

**校准协议：** 交付时若三级来源占多数，必须在 Executive Summary 的「下一步」里列出品牌方需要提供的数据清单——量化层从「占位」变成「可拍板」的钥匙在客户手里，不在我们手里。

**沉淀路径：** 经客户确认有效的行业基准，复盘时写入案例库与记忆（标来源与时点），供下一次交付复用——经验靠验证积累，不靠生成时编造。

### 媒介内容的交付边界

媒介内容严格限于以下范围：

**可以包含：**
- 平台选择方向与理由（为什么选小红书而非抖音）
- 平台角色分工（小红书做信任、抖音做声量、点评做收口）
- 内容策略方向（什么类型的内容在什么平台、面向什么人群）
- KOL 层级建议（头部做曝光、腰部做圈层、KOC 做搜索占位）——不指定具体达人
- 投资概览（按来源纪律填实或占位的预算结构表）
- 阶段节奏（先铺内容再放量还是同步进行）

**不包含：**
- 无来源依据的精确预算金额或百分比
- 具体达人推荐名单
- 无来源的渠道 ROI 或转化成本估算
- 无来源的 CPM/CPC/CTR 等投放效果指标预测值
- 广告投放操作建议（出价策略、定向设置、素材规格）

**强制标注：** 媒介相关内容必须标注"以下建议基于行业基准和公开案例推断，未基于品牌实际投放数据。具体执行需在投放测试后校准。不接受将方向性建议作为精确预算分配依据。"

> 背景：媒介策划是六个模块中数据依赖最重的一个模块。在当前个人开发者环境下，渠道 ROI、投放效果等核心数据完全不可得。交付件中的媒介内容定位于"帮客户理清方向"，而非"替客户做投放决策"；投资额与目标值按三级来源纪律处理，实际的投放执行和优化由客户或其代理商基于真实数据完成。
